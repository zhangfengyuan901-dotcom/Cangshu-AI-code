# 仓鼠AI开发规则

继承父目录规则。版本与未完故障读 `../.agents/project-state.json`，不在此追加发布流水账。

## 构建与验证

- 主工程保存当前已验证开发源，官网分发版本在项目状态中单独记录。未验证改动先在独立分支或隔离目录验证。`release/source-manifest.json` 固定应用运行源码、依赖锁、构建与资源输入。
- 当前构建规格为 `release/current.json`。`npm run release:check` 仅校验源码输入。`npm run release:stage` 在工作区外重建画布、Python 运行资源和安装依赖，不读取已生成的 EXE、ASAR 或历史发布目录。`npm run dist` 使用同一入口构建独立安装包。首次打包先用 `npm ci` 安装 Electron 工具链。Windows 构建环境需提供 uv 与 7-Zip，可用 `HAMSTER_BUILD_UV` 和 `HAMSTER_BUILD_7ZIP` 指定。
- Node回归：`npm test`；Python按当前任务运行 `smart-video-agent/test_*.py`，使用实际可用解释器。涉及已发行问题，验证实际包，不能只验开发树。
- 媒体、账户、计费、隔离及防重修改要覆盖正常与故障边界。模拟、包校验、EXE启动和真实收费验收分别表述。
- 客户端发行包仅使用用户指定的网盘分享；禁止将安装包上传R2或通过官网直传。官网按钮、教程和旧下载入口统一指向 state 中的当前网盘链接，并展示提取码。发布工具不得保留可执行的R2安装包上传步骤。

## 账户与数据

- 账户页显示中转站账户数据与本机连接状态。注册、登录和充值通过固定中转站入口打开系统浏览器；当前正式版和改造候选的执行状态见 state。首次连接使用短期随机授权引用和主进程独有证明，网页须明确同意连接。会话令牌、证明及 Key 只由主进程处理，使用系统保护存储。应用返回前台后按服务端结果刷新余额。
- 登录身份须与受保护本机 Key 的账号归属一致。网页建单再次核对连接绑定账号与当前登录身份，已有本机账号对匿名重连也构成限制。首次开通按账号和用途幂等创建应用 Key，主进程只补齐本机缺失项。重试和重启须恢复同一授权，已有未知操作保留核对信息；付款跳转不代表到账。
- 图片、视频、工具、对话四用途属于同一PIKNO账户、共用余额；数字人/深度用工具Key，对话专用 `chat-standard`。免费检测不上传、不建任务、不扣费。
- Electron系统加密与原子事务保存Key，renderer不接收、存储或回显。共享上游Key/接入点仅在受控网关Secret；短期令牌只驻内存。
- 操作固定账户opaque scope、配置revision、Key与持久operation。切账户/换配置使旧异步结果失效；同账户换Key不改变历史归属，跨账户文件/响应引用拒绝。
- 更新保留AppData身份、配置、聊天、附件、画布绑定、素材、任务与结果。空白Key保留原值，移除只清本机对应Key。
- 源码调试的配置和会话数据位于工作区外。Windows 默认使用 LocalAppData 下的 `HamsterAI-WorkspaceData/app`。仅在调试启动时可用绝对路径 `HAMSTER_WORKSPACE_DATA_DIR` 指定位置。

## 生成与对话

- 媒体报价、名称、规格与售价由已发布服务端目录提供。工作台和创作画布在点击生成后后台静默核价，按整批总价核对对应账户余额；余额不足时阻止提交并提示前往账户充值。缺价、过期、变参、变价或换账户须重新核价。只读报价不提交；提交时保留原子余额校验。批量按单份持久幂等，停止只阻止未发送份数，重启不续发。
- 视频生成参考素材由素材服务保存到私有 TOS 桶。图片参考素材先受控保存本机，随图片编辑请求以原文件 multipart 直传；数字人和黑白深度素材通过受控中转直传上游。图片和工具结果通过固定允许域地址或受限 Base64 取回本机。工具配置、任务状态和防重记录保留在 TOS 的独立对象键范围；生产发布不绑定 R2。
- 新对话只通过 PIKNO 调用 `doubao-seed-2.1-pro`。各功能以 PIKNO 中转站发布的价格和账单为准。对话按 `actual_usage_v1` 使用可信的实际用量结算，无需逐条确认费用。旧账本按原价版查询，禁止追改或重复计费。
- 对话保留零金额在途占位、单用户在途与至多一次可能计费执行。模型不可用时禁止切换到其他模型。受理或结果未知后禁止重试。
- unknown原请求保留；新消息仅在服务器严格 `admission_blocking=false` 且同scope/revision后开放。900秒只用于安排重新查询，本机时间不能授权。账务核对与回答展示分离，不把失败说成成功。
- 对话输入框不展示单价。素材入口按 PIKNO 下发的能力和同账户视频用途连接显示。豆包图片和视频画面通过现有私有 TOS 链路上传，单图至多 10 MB，单视频至多 50 MB 和 3 分钟。历史本地对话和附件保留。新请求仅使用当前模型支持的附件。
- 原请求未知、创建Key或付款响应未知，只查原operation，不换编号重发。正常已审查回答先保存显示，后台有限核对；停止/重启不自动重发。

## 本地服务和集成

- 视频反推独立使用 `reverse.cjs`、`reverse-client.cjs`、`reverse-media.cjs` 和 `public/reverse.mjs`。本机 `/api/reverse/*` 读取工具Key与执行快照；视频由Node直PUT上游预签名对象存储，中转站仅收JSON。文件限500MiB/600秒，真实容器元数据校验不代替上游最终时长。报价须显式确认；上传与分析各自持久operation，未知只查原请求。账务以中转站可信结果为准，不在客户端结算。
- 反推支持本地文件和单个受支持平台链接；`url` 与 `upload_id` 严格二选一。分享文案只在本机提取链接，不联网探测；链接须通过客户端和服务端相同的官方域名/视频路径白名单，签名query原样转发且不记录URL。链接模式仅在服务端 `input_modes` 明确包含 `link` 时开放，不走上传/下载；旧服务保持文件功能。输入模式不改变报价、18元确认、账户隔离或原operation恢复。

- 保留精确loopback Host/Origin、当前动态端口CSP与导航限制。聊天HTML `no-store`，入口instance绕过旧新鲜缓存；不放宽frame-ancestors解决空白。
- 本机Codex由用户选目录，独立CLI身份与会话，始终只读；不读取auth.json、不复用PIKNO凭据，不执行命令/改文件/扩展工具。
- 正式产品不提供ChatCut与独立图片编辑入口、运行模块或专属调用分支。移除功能不删除客户已有文件、任务、历史、素材或结果；图片生成、参考素材、数字人和创作画布保持各自功能。
- Hypit内部使用、不公开捆绑；保留原版许可证及独立任务/报价/确认/防重。Codex/Hypit模块按点击加载；隐藏页暂停普通轮询，恢复单飞。UI调度不改变服务端计费和任务语义。

## 客户界面与反馈

- 客户界面不暴露上游品牌、域名、技术ID、原始异常、内部字段或成本公式；用户明确允许的PIKNO入口/线路及售价可显示。
- 正式版沿用后台脱敏反馈，客户端/云端双白名单：版本、固定模块/错误码、系统架构、数值状态、受限文件名/行号。禁止正文、素材、客户路径/IP/身份、Key/令牌和原始堆栈。QA不真实上报，失败退避不影响任务、不递归。
- 故障报告 Worker 仅在 D1 保存脱敏报告，保留 30 天。禁止写入 R2 或投递故障邮件。
- 按任务读源码：账户 `electron/account-*.cjs`；生成 `pikno*.cjs`/`tasks.cjs`；对话 `smart-video-agent/chat.py`/`chat_media.py`/`chat-ui/` 与对应测试；工作流同步 `electron/workflow-sync.cjs`。运行时细节可按需读 `docs/portable-runtime.md`、`docs/task-lifecycle.md`。

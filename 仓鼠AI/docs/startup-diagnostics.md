# 故障反馈（1.7.39）

发布版遇到异常时在后台自动反馈脱敏信息，不弹上传确认、不要求手动导出。账户页已移除「启动诊断」面板，保留折叠的「故障反馈与隐私说明」。正常业务错误提示及重试操作仍保留。

仅反馈版本、系统类型/架构、故障分类、数值状态码/退出码和程序代码位置。不上传密钥、提示词、聊天、素材、完整路径、原始报错或完整堆栈。断网时暂存并在应用运行且网络恢复时补报；同类故障合并。待发记录最多100条、保留30天，云端按30天保留策略自动清理。

覆盖启动失败、渲染进程退出、可捕获的主进程异常、生成/结果保存失败、服务错误、智能体/创意处理异常和页面未处理异常。断电、系统强制终止、磁盘不可写可能无法留下记录；无错误事件的体验问题仍需客户描述。自动反馈不代表自动修复，也不重发付费生成请求。

## 以下为1.7.27历史实现存档（内部，非现行客户操作）

## 客户怎么操作

1. 在发生问题的电脑重新点击主应用左侧「工作台」，或浏览器工作台中的「仓鼠智能体」「创意工作台」。
2. 启动失败时，弹窗显示错误类型；点击「导出诊断信息」。也可在「账户 → 启动诊断」检测和导出。
3. 将桌面 **仓鼠AI诊断** 文件夹中最新的 `仓鼠AI-启动诊断-*.json` 发给支持人员。
4. 不要发送 `config.json` / `config.yaml`、密钥截图或整个用户数据目录。

1.5.1 以前的版本没有保存启动日志，不能在升级后补回旧日志，需要复现一次。1.6.0 已内置离线运行环境，并在端口不可用时自动切换；仍失败时按本页导出。诊断功能用于缩小原因范围，不保证自动修复所有环境问题。

## 记录哪些信息

- 应用版本、操作系统版本与架构、内置 Node/Electron 版本。
- 工作台端口是否空闲、是否属于本应用服务；Windows 下尽可能附上占用进程名和 PID。
- 工作流、Python 和内置环境启动器是否存在；三类密钥仅报告「已配置/未配置」。
- 最近一次启动失败、退出码，以及筛选和脱敏后的启动日志。

不导出密钥明文、完整环境变量、完整进程命令行、任务记录、提示词、用户素材或生成文件。日志中的已知密钥、常见凭据、签名链接路径/参数和用户主目录会被隐藏；业务期 stdout/stderr 不进入诊断日志。

诊断文件只在用户点击导出后保存到本机，不会自动上传。

## 常见错误分类

| 代码 | 含义与建议 |
| --- | --- |
| PORT_IN_USE | 端口被占用；核对进程归属，不要随意结束其他软件 |
| PORT_UNAVAILABLE | 端口不可用，可能是权限、安全软件或系统保留策略 |
| DEPENDENCY_MISSING | Python 模块缺失或导入失败，检查内置环境完整性与安全软件隔离记录 |
| NETWORK_SETUP_FAILED | 下载、连接、证书或网络异常，检查客户网络和代理 |
| PERMISSION_DENIED | 文件或端口权限受限，检查安全软件和文件夹权限 |
| RUNTIME_MISSING / WORKFLOW_MISSING | 安装文件或运行环境缺失 |
| WORKFLOW_VERSION_MISMATCH | 正在运行旧版本工作台 |
| STARTUP_FAILED | 未归类的启动异常，需要结合日志进一步排查 |
| STARTUP_TIMEOUT | 服务未在时限内通过健康检查，已停止本次启动进程 |

端口检测与真正绑定之间存在时间窗口；后续绑定错误仍会写入日志。程序不会自动终止占用端口的其他进程。

## 本地文件与保留策略

启动日志在主应用 `config.json` 同级的 `diagnostics` 文件夹中；打包版为 Electron 用户数据目录。`startup.log` 每份约 512 KiB，最多保留当前日志及两份轮转日志。`last-failure.json` 保留最近失败摘要。

如果日志目录不可写，当前会话保留有限内存日志，诊断页会提示；导出仍会尝试使用内存记录。桌面目录也不可写时会明确报告导出失败。桌面导出的文件由客户自行管理。

应用初始化阶段（工作流复制或本地 HTTP 服务启动失败）也会弹出原生导出提示。正常关闭应用导致的子进程退出不记作启动失败。

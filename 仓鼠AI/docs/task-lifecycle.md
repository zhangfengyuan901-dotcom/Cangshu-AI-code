# 1.7.49 PIKNO 任务与恢复补充

本节优先于下方 1.7.25 历史记录。新版每次报价确认绑定参数、账户、版本和份数；批次与单份身份在收费请求前持久化。2／4 份快速返回本地受理，首份请求不再占住页面连接；“停止剩余”只阻止未发送份，不取消已提交任务或表示退款。关闭、重启、变更 Key 或未知结果均不自动恢复剩余收费提交。

- unknown／submitting 即使没有任务 ID 也不允许由“清除已结束记录”删除。已明确失败及已保存成功记录按原规则清理；批次去重回执保留，不删除桌面结果。
- 有原 ID 的视频／工具只查询原 ID。历史工具可使用独立验证且同账户、有明确读取权限的客户 Key；新工具 POST 仍必须用工具 Key。
- 无 ID 的未知图片或视频提交暂不保证自动恢复；保留原关联身份，引导在 PIKNO 核对，不视为失败或退款，不重新创建。
- 保存失败保留生成成功状态；仅查询原任务和重试保存。临时链接过期不保证能刷新，不为获取结果重发生成。
- 已有旧数据、名称及原报价快照保持；每张任务卡的整批报价不能相加当成实际消费，实际结算以 PIKNO 为准。

下面保留旧版机制与接口记录，仅供历史兼容参考。

# 本地任务生命周期（1.7.25）

依据：https://sanbaobeauty.com/docs.html（2026-09-13 核对）。

## 范围

主应用的图片生成、视频生成、数字人和黑白深度任务。智能成片与创意工作台仍使用各自的工作流记录，本次不改写其工作流执行器。

## 提交与记录

1. 本地服务先写提交记录；无法写盘时不向上游发送付费请求。
2. 图片、视频、数字人和黑白深度请求都携带本次提交的 `Idempotency-Key`。本地记录成功后立即向页面返回 `202 Accepted` 和本地任务卡；上游创建在后台继续，不占用页面提交按钮。
3. 上游响应后逐条保存 `tasks[].task_id`，兼容 `taskId` / `id` 和单任务响应；本地任务卡随后从“已提交”切换为排队、生成中或明确失败。没有请求异步响应的旧调用仍保持同步代理兼容。
4. 每个任务单独 JSON 文件，先写临时文件、fsync，再原子替换。记录不再依赖浏览器 localStorage，不截断为最近 200 条。
5. 打包版记录位置为 Electron 用户数据目录下的 `task-history`，与 config.json 同级，不受启动端口和版本目录影响。安装版与便携版均保留用户数据；卸载时主动清除用户数据、删除记录目录不在保留保证内。
6. 不在任务记录中保存 API Key，只记录指纹；运行时或配置中的原 Key 用于查询。更换账号后不把旧任务自动发给新账号。

## 查询与恢复

- 应用本地服务启动时扫描未完成任务，按原 ID 查询；页面只读取本地任务快照。
- 图片：`GET /openapi/v1/images/{taskId}`；视频：`GET /openapi/v1/videos/{taskId}`。工具类仍使用其原查询接口与共用工具 Key。
- `preparing` 视作排队；`queued` / `processing` 持续查询。只有上游明确 `failed` 才判定生成失败。
- 正常查询间隔约 5 秒，同时最多 2 个任务处理。网络/响应异常指数退避，最高 60 秒；429 遵守 `Retry-After`（安全上限一小时）。鉴权异常保留任务并提示检查原 Key。
- 任务完成后先落盘状态和链接，再下载。下载失败与生成失败分开；自动重新查 ID 刷新签名 URL 后重试，保存重试间隔最高 5 分钟。
- 完全退出程序或关机时，本地服务无法继续轮询和下载。重开应用自动恢复；不会重新创建付费任务。
- 提交过程中断而未收到 ID，记录显示“提交待确认”。不得自动重新提交，需核对服务端记录以免重复扣费。

## 保存与预览

- 默认下载到桌面 `仓鼠AI生成结果`。按任务生成确定性文件名，写 `.part` 后再改名；下载失败移除本次不完整文件。
- 单次查询 30 秒超时，单次下载 5 分钟超时，超时后保留记录重试。
- 本地预览使用按任务授权的文件端点；不允许读取结果目录以外的文件，支持 HEAD、Range、视频拖动进度以及本地文件下载。
- 本地文件可用后停止上游轮询，预览不依赖 24 小时签名链接。检测到文件被移走或删除时，尝试查询原 ID 重新保存。
- 已完成预览按任务增量更新，不因其他任务进度更新而反复重建播放器。
- “清除已结束记录”需要确认；保留进行中和等待保存的任务，且不删除桌面结果文件。

## 历史迁移与边界

- 自动迁移当前浏览器来源可读的旧 localStorage 历史，导入幂等，原备份不删除。
- 旧版随机端口产生的其他浏览器来源历史不保证可读；旧版从未保存的进行中 ID 不能凭空恢复。
- 上游任务或源文件若已被永久删除，客户端不能保证恢复。恢复失败会保留任务与错误信息，不伪装成功。
- 读取失败的记录文件不覆盖、不删除，界面提示检查备份。

`scripts/qa-task-server.cjs` + `scripts/qa-task-ui.js` 提供全本地上游替身，验证清除 localStorage 后重开仍能恢复、保存并预览。没有真实付费生成调用。
